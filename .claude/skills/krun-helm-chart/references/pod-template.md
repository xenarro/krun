# Pod template contract (SPEC.md:1363-1412)

One `_helpers.tpl` partial per concern (`krun.podSecurityContext`,
`krun.containerSecurityContext`, `krun.probes`, `krun.configEnv`,
`krun.labels`), included from every pod template, so a fix lands in all.
Every pod: gateway Deployment, scheduler Deployment, embedded StatefulSet,
migrate hook Job, every init container, and the Litestream native sidecar
(itself an init container) (SPEC.md:1363-1365).

## Chart layout

```
deploy/helm/krun/
  Chart.yaml                 apiVersion v2, name krun, version/appVersion 0.0.0 (P0.2); stamped on v* tags
  values.yaml                references/values.md verbatim; helm-docs comments on every key
  README.md                  generated by helm-docs in make generate (P7.5); never hand-edited
  templates/NOTES.txt        egressCIDRs warning; install hints
  templates/_helpers.tpl     names, labels, selector labels, pod/container securityContext, probes, config env
  templates/_validate.tpl    the fail cases, included once
  templates/crd-functions.yaml       GENERATED (scripts/gen-crd.ts), crds.install + keep
  templates/gateway-deployment.yaml  postgres mode
  templates/scheduler-deployment.yaml postgres mode
  templates/migrate-job.yaml, migrate-serviceaccount.yaml   postgres hooks
  templates/statefulset.yaml, headless-service.yaml         embedded mode
  templates/service-public.yaml, service-internal.yaml      krun-gateway-internal is a fixed name
  templates/pdb.yaml, serviceaccounts.yaml, rbac-krun.yaml, rbac-jobs.yaml
  templates/networkpolicy-krun.yaml, jobs-namespace.yaml, networkpolicy-jobs.yaml, limitrange.yaml, resourcequota.yaml
  templates/admission-policy.yaml     ValidatingAdmissionPolicy + binding krun-jobs-digest (cluster-scoped)
  templates/httproute.yaml           gatewayApi.httpRoute.enabled
  templates/podmonitor.yaml, prometheusrule.yaml
```

File names are a suggestion; rendered kinds and conditions are not. One
kind per file, so `helm template --show-only` targets a test.

## Labels (SPEC.md:990-994)

| Label | Where | Why |
|---|---|---|
| `app.kubernetes.io/name: krun` | every pod template, selectors, PodMonitor | deny-all and admin-port policies, PodMonitor select by it |
| `app.kubernetes.io/instance: {{ .Release.Name }}` | every pod template, selectors, PodMonitor | same |
| `app.kubernetes.io/component: gateway|scheduler|krun|migrate` | per workload | Deployment selectors must differ; not SPEC-mandated, standard |
| `krun.io/gateway: "true"` | gateway Deployment and embedded StatefulSet pod templates ONLY | 8080/8081 ingress and the jobs-namespace 8081 egress select it (SPEC.md:991-994, 1017-1018) |
| `helm.sh/chart`, `app.kubernetes.io/managed-by`, `app.kubernetes.io/version` | metadata labels only | never in selectors (immutable); see `kubernetes-skill` helm-patterns.md |

Never put `krun.io/gateway` on the scheduler Deployment or the hook Job:
it opens 8080/8081 to them and admits them as "gateway" peers.

## Security context (SPEC.md:1319-1324)

Pod level:

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 65532
  runAsGroup: 65532
  seccompProfile: { type: RuntimeDefault }
  # embedded StatefulSet only (SPEC.md:1350-1351):
  fsGroup: 65532
  fsGroupChangePolicy: OnRootMismatch
```

Every container, init container and native sidecar:

```yaml
securityContext:
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: [ALL] }
  runAsNonRoot: true
  runAsUser: 65532
  runAsGroup: 65532
  seccompProfile: { type: RuntimeDefault }
```

Plus `volumes: [{ name: tmp, emptyDir: {} }]` mounted at `/tmp` on every
container (SPEC.md:1323). 65532 is distroless `nonroot` (SPEC.md:1321).
`runAsNonRoot`/`seccompProfile` at both levels is deliberate, as in KEDA's
operator (keda `config/manager/manager.yaml:25-26,74-82`). PSA
`restricted` accepts either, but a future container added without the
partial would fail admission with a confusing message (knative serving
`secure-pod-defaults` does the same per container,
`pkg/apis/serving/v1/revision_defaults.go:206-264`). The Litestream image
must also run as 65532. An image that needs root is BLOCKED, not a
`runAsUser` override.

`automountServiceAccountToken`:

- `true` only on gateway and scheduler pods. They read Functions, the
  Lease, and `KRUN_NAMESPACE` from the SA namespace file (SPEC.md:1324, 1197).
- `false` on the migrate hook pod, the `krun-migrate` SA
  (SPEC.md:1345-1346) and `krun-job-default` (SPEC.md:1032-1033).
- Embedded mode: the one pod mounts the scheduler SA token
  (SPEC.md:1352-1354).

## Probes (SPEC.md:1327-1331)

| Probe | Path | Port | periodSeconds | timeoutSeconds | failureThreshold |
|---|---|---|---|---|---|
| readiness | `/readyz` | the container's own admin port name | 5 | 3 | 3 |
| liveness | `/healthz` | the container's own admin port name | 10 | 3 | 3 |
| startup | none | | | | |

Liveness on `/readyz` would restart a healthy standby, or a pod whose
database stalls for 2 s (SPEC.md:1161-1164). No `initialDelaySeconds`, no
startup probe: `/healthz` answers once the listener is up (SPEC.md:1161).
Do not copy KEDA's `initialDelaySeconds: 25` / `20` probes or its 10 s
grace: they compensate for a `Ping` handler and no in-flight work. krun's
`/readyz` already waits for the informer, and 30 s covers both drains
(keda `config/manager/manager.yaml:47-56`, `cmd/operator/main.go:352-359`;
SPEC.md:1161-1174).

Port names: `admin` (9090) on gateway, scheduler and the embedded gateway
container; `admin-sched` (9091) on the embedded scheduler container, with
`KRUN_ADMIN_LISTEN_ADDR=:9091` (SPEC.md:1356-1358). Also declare `http`
8080 and `internal` 8081 on gateway containers. Services target the
numeric ports.

## Resources (SPEC.md:1233, 1236, 1331)

Default `requests: { cpu: 100m, memory: 128Mi }`, `limits: { memory: 512Mi }`,
rendered with `toYaml .Values.gateway.resources` / `.scheduler.resources`.
No CPU limit by default: a throttled Node event loop inflates every
latency metric and makes probes flap. The migrate hook, init containers
and Litestream native sidecar reuse the scheduler resources. SPEC fixes no
separate value and no task asks for one (PLAN.md:31-32).

## Scheduling and lifecycle

| Field | Value | Where | SPEC |
|---|---|---|---|
| `priorityClassName` | `.Values.priorityClassName` when non-empty (`with`) | every pod | SPEC.md:1237, 1332 |
| `terminationGracePeriodSeconds` | `.Values.terminationGracePeriodSeconds` (30) | every pod | SPEC.md:1238, 1332; both shutdown sequences fit 30 s (SPEC.md:1174) |
| `strategy` | `RollingUpdate`, `maxSurge: 1`, `maxUnavailable: 0` | scheduler Deployment | a Ready standby exists before the leader gets SIGTERM; the old leader clears `holderIdentity` and the standby takes over at once (SPEC.md:1335-1337, 1171-1173) |
| `strategy` | Deployment default (`25%/25%`) is acceptable; nothing in SPEC fixes it | gateway Deployment | drain makes `/readyz` 503 for `shutdownDelay` first (SPEC.md:1166-1170) |
| `topologySpreadConstraints` | `maxSkew: 1`, `topologyKey: kubernetes.io/hostname`, `whenUnsatisfiable: ScheduleAnyway`, `labelSelector` = the gateway selector | gateway Deployment | SPEC.md:1334-1335; `ScheduleAnyway` so a one-node kind cluster still schedules both replicas |
| PodDisruptionBudget | `policy/v1`, `minAvailable: 1`, selector = gateway selector | only when `gateway.replicas > 1` | SPEC.md:1333-1334; a PDB with `minAvailable: 1` on a single replica blocks node drains forever |
| `restartPolicy` | `Always` (default) | Deployments, StatefulSet | |
| `nodeSelector`, `tolerations`, `affinity` | none | | no task asks; adding them is PLAN.md:31-32 scope creep |

Lessons: knative's autoscaler uses `RollingUpdate maxUnavailable: 0` for
the same leader handover (serving `config/core/deployments/autoscaler.yaml:29-32`).
knative sizes `terminationGracePeriodSeconds` to the longest drained
request (600 s, `config/core/deployments/activator.yaml:118-126`); krun's
gateway closes `wait`/SSE at shutdown, so 30 s is enough (SPEC.md:1169-1174).
dapr gates its PDB on an HA flag with configurable `minAvailable` or
`maxUnavailable`; krun keeps `minAvailable: 1` gated on `replicas > 1`
(dapr `.../dapr_operator_poddisruptionbudget.yaml:1,18-22`; SPEC.md:1333-1334).

No PDB for the scheduler: one replica is the default, and the standby
pattern tolerates loss (SPEC.md:1235). knative's `minAvailable: 80%` on
autoscaled components (`config/core/deployments/activator-hpa.yaml:53`)
does not apply; krun's fixed `1` matches its fixed small replica counts.

## `config` env (SPEC.md:1240, references/values.md)

Render one `- name: KRUN_<SNAKE>` / `value: {{ . | quote }}` pair per
`config.*` key on every krun container (gateway, scheduler, both embedded
containers, migrate hook). Always `quote`: Helm turns `86400` into an int,
and the env API needs a string. Secret-backed env uses
`valueFrom.secretKeyRef`, never a value:

| Env | secretKeyRef | Containers |
|---|---|---|
| `KRUN_DB_DSN` | `{{ .Values.db.postgres.existingSecret }}` key `dsn` | gateway, scheduler, migrate hook (postgres mode) |
| `KRUN_S3_ACCESS_KEY`, `KRUN_S3_SECRET_KEY` | `objectStorage.existingSecret` keys `accessKey`, `secretKey` | gateway and scheduler when `objectStorage.enabled` |
| `KRUN_WEBHOOK_SECRET` | `webhooks.existingSecret` key `secret` | scheduler (both modes) when `webhooks.allowedHosts` non-empty |
| `LITESTREAM_ACCESS_KEY_ID`, `LITESTREAM_SECRET_ACCESS_KEY` | `envFrom.secretRef` `db.embedded.litestream.existingSecret` | Litestream restore init container and native sidecar |

Optional env, each rendered only when its value enables it (PLAN P7.4d;
references/values.md):

| Env | Value | Containers | Gate |
|---|---|---|---|
| `KRUN_JOB_HOST_USERS` | `"false"` | scheduler (embedded: the scheduler container) | `jobsNamespace.userNamespaces` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `observability.otlpEndpoint` | gateway and scheduler (both embedded containers) | `otlpEndpoint` non-empty |
| `OTEL_TRACES_SAMPLER` | `parentbased_traceidratio` | same | same |
| `OTEL_TRACES_SAMPLER_ARG` | `observability.tracesSampleRatio`, quoted | same | same |
| `OTEL_SERVICE_NAME` | `krun-gateway` or `krun-scheduler`, per container, not per pod | same | same |

The migrate hook, the `migrate` init container and the Litestream
containers get none of these. A `krun.otelEnv` partial taking the service
name keeps the four in one place.

API keys are a volume, not env: `secret.secretName: {{ .Values.apiKeys.existingSecret }}`
mounted `readOnly: true` at `/etc/krun` with no `subPath`, so the 30 s poll
sees the kubelet symlink swap on Secret update (SPEC.md:954-956, D12).
`krun migrate` reads only `KRUN_DB_*` (SPEC.md:1346-1347): the hook needs
`KRUN_DB_MODE` and `KRUN_DB_DSN`, plus the rest of `config` for uniformity
(harmless).

## Postgres mode (SPEC.md:1339-1347)

Two Deployments (`<fullname>-gateway`, `<fullname>-scheduler`), two
ServiceAccounts with their RoleBindings, and the hook pair:

```yaml
# templates/migrate-serviceaccount.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: krun-migrate
  annotations:
    helm.sh/hook: pre-install,pre-upgrade
    helm.sh/hook-weight: "-5"
    helm.sh/hook-delete-policy: before-hook-creation,hook-succeeded
automountServiceAccountToken: false
---
# templates/migrate-job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ include "krun.fullname" . }}-migrate
  annotations:
    helm.sh/hook: pre-install,pre-upgrade
    helm.sh/hook-weight: "0"
    helm.sh/hook-delete-policy: before-hook-creation,hook-succeeded
spec:
  backoffLimit: 1
  activeDeadlineSeconds: 240
  template:
    metadata: { labels: ...name/instance/component: migrate }   # no krun.io/gateway
    spec:
      serviceAccountName: krun-migrate
      automountServiceAccountToken: false
      restartPolicy: Never
      securityContext: ...pod partial
      containers:
        - name: migrate
          image: ...
          args: [migrate]          # bin/krun.js dispatch (PLAN.md:95)
          env: KRUN_DB_MODE, KRUN_DB_DSN (secretKeyRef) + config env
          securityContext: ...container partial
          volumeMounts: [{ name: tmp, mountPath: /tmp }]
      volumes: [{ name: tmp, emptyDir: {} }]
```

Why each piece:

- SA is a hook resource: hooks run before the release's regular
  resources exist, so a plain SA would be missing when the Job runs
  (SPEC.md:1343-1345). Weight `-5` before `0` orders SA before Job.
- `before-hook-creation` removes the previous Job first (a Job template is
  immutable, so re-applying would fail). `hook-succeeded` leaves a FAILED
  Job in place for `kubectl logs` (SPEC.md:1340-1342).
- No Role: `krun migrate` talks only to Postgres (SPEC.md:1345-1347).
- `backoffLimit: 1` gives one retry on a transient DSN error.
  `activeDeadlineSeconds: 240` bounds a hung migration below Helm's default
  5-minute `--timeout` (SPEC.md:1342).
- No probes (a Job pod); every other part of the contract applies.
- The DSN comes from `existingSecret`, so the hook can read it at
  `pre-install` time. A chart-rendered Secret would not exist yet
  (SPEC.md:1309-1310); hence the chart renders no Secret.

`dapr` uses no Helm hooks (CRDs under `crds/`, a long-running operator).
The hook pattern follows the Helm docs and the `helm-chart-scaffolding`
reference `chart-structure.md:438-451`, with krun's weights and bounds
from SPEC.

## Embedded mode (SPEC.md:1393-1412)

One StatefulSet `<fullname>`, `replicas: 1`, `serviceName` = a headless
Service (`clusterIP: None`, no `ports`, selector name+instance,
SPEC.md:1355-1356). The pod runs as the scheduler SA; no gateway SA or
RoleBinding renders (SPEC.md:1352-1355). The pod template carries
`krun.io/gateway: "true"` (SPEC.md:991-992).

```yaml
spec:
  serviceAccountName: {{ include "krun.fullname" . }}-scheduler
  securityContext: { ...pod partial, fsGroup: 65532, fsGroupChangePolicy: OnRootMismatch }
  initContainers:
    {{- if .Values.db.embedded.litestream.enabled }}
    - name: litestream-restore
      image: {{ .Values.db.embedded.litestream.image }}
      command: [/bin/sh, -c]
      args:
        - |
          set -eu
          if [ ! -f /data/krun.db ]; then rm -f /data/krun.db-wal /data/krun.db-shm; fi
          litestream restore -if-replica-exists -if-db-not-exists -o /data/krun.db {{ .Values.db.embedded.litestream.url }}
      envFrom: [{ secretRef: { name: {{ .Values.db.embedded.litestream.existingSecret }} } }]
      volumeMounts: [{ name: data, mountPath: /data }, { name: tmp, mountPath: /tmp }]
      securityContext: ...container partial
    - name: litestream              # native sidecar: runs for the pod's lifetime
      image: {{ .Values.db.embedded.litestream.image }}
      restartPolicy: Always         # this field is what makes an init container a sidecar
      args: [replicate, /data/krun.db, {{ .Values.db.embedded.litestream.url }}]   # assumes the image entrypoint is litestream
      envFrom: [{ secretRef: { name: {{ .Values.db.embedded.litestream.existingSecret }} } }]
      volumeMounts: [{ name: data, mountPath: /data }, { name: tmp, mountPath: /tmp }]
      securityContext: ...container partial
      resources: ...scheduler resources
    {{- end }}
    - name: migrate
      image: krun
      args: [migrate]
      env: KRUN_DB_MODE=embedded (+ config env)
      volumeMounts: [{ name: data, mountPath: /data }, { name: tmp, mountPath: /tmp }]
  containers:
    - name: gateway      # ports http 8080, internal 8081, admin 9090; probes on admin
    - name: scheduler    # KRUN_ADMIN_LISTEN_ADDR=:9091; port admin-sched 9091; probes on admin-sched
    # no Litestream entry here: it is the native sidecar above
  volumes: [{ name: tmp, emptyDir: {} }]
volumeClaimTemplates:
  - metadata: { name: data }
    spec:
      accessModes: [ReadWriteOnce]
      {{- with .Values.db.embedded.storageClass }}
      storageClassName: {{ . }}
      {{- end }}
      resources: { requests: { storage: {{ .Values.db.embedded.storage }} } }
```

Order (SPEC.md:1403-1410): restore, sidecar, migrate. Never a Litestream
entry under `containers`: a regular container races the app containers at
shutdown and can miss the last WAL frames (D36).

- Restore before migrate: `krun migrate` on an empty `/data` creates a
  fresh database, and `-if-db-not-exists` then skips the restore.
- Sidecar after restore, so it replicates the restored database, not a new
  generation from an empty file. Before migrate, so migration writes
  stream too.
- The kubelet starts the native sidecar, then moves to the next init
  container (no startup probe needed; SPEC sets none). It keeps the
  sidecar running beside the app containers. On termination it stops the
  sidecar only after gateway and scheduler exited, so their last WAL
  writes ship (D36).
- The sidecar shares the pod's `terminationGracePeriodSeconds`. 30 s
  covers both drains and Litestream's final sync.
- No krun probes on the sidecar: it is not a krun container
  (SPEC.md:1371-1374 names krun containers only).
- Remove orphan `-wal`/`-shm` first: a stale WAL next to a restored
  database corrupts it (docs/OPERATIONS.md:99-105 is the drill).
- The Litestream image must contain `/bin/sh` for the two-step script. If
  the image is distroless, split into two init containers (`rm` needs a
  shell; `litestream` does not). This implements SPEC's "removes orphan
  files then restores" step; it is not a new option.

- `storageClassName` uses `with` (an `if` guard), never `{{ .Values...storageClass | quote }}`:
  `storageClass: ""` rendered with `quote` pins the PVC to "no class" and
  disables dynamic provisioning (SPEC.md:1264, 1351-1352; dapr guards the same way in
  `charts/dapr/charts/dapr_scheduler/templates/dapr_scheduler_statefulset.yaml:27-29`).
- `fsGroup: 65532` with `OnRootMismatch` makes the PVC writable by the
  nonroot user without a recursive chown on every start (SPEC.md:1350-1351).
- SQLite WAL mode supports both processes on one local volume. Network
  filesystems are unsupported; the README must say so (SPEC.md:1362-1364).
- `updateStrategy` is the StatefulSet default `RollingUpdate`. With one
  replica an upgrade means brief downtime (SPEC.md:1412,
  docs/OPERATIONS.md:33-34). Keep it, and any scheduler outage, below
  `config.ttlAfterFinished` (SPEC.md:1416-1417).

## HTTPRoute (SPEC.md:1329-1333, 1423-1424; PLAN P7.4d)

Rendered only when `gatewayApi.httpRoute.enabled`:

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: {{ include "krun.fullname" . }}
  labels: ...chart labels
spec:
  parentRefs: {{- toYaml .Values.gatewayApi.httpRoute.parentRefs | nindent 4 }}
  {{- with .Values.gatewayApi.httpRoute.hostnames }}
  hostnames: {{- toYaml . | nindent 4 }}
  {{- end }}
  rules:
    - backendRefs:
        - name: {{ include "krun.fullname" . }}-gateway   # the public Service
          port: 8080
```

- One rule, one backend: the public Service. Never `krun-gateway-internal`
  (8081 is reachable only from the jobs namespace), never an admin port.
- The backend is in the route's own namespace: no ReferenceGrant. A
  Gateway in another namespace must admit krun-namespace routes through
  its `allowedRoutes`; that is the platform team's Gateway, not the chart.
- `krun-allow-public` already admits 8080 from anywhere, so the Gateway's
  data plane reaches the pods without a new NetworkPolicy.
- `:wait` holds a request up to `KRUN_MAX_WAIT` (60 s); `:watch` is a
  long-lived SSE stream. A Gateway's default request timeout may cut them.
  The chart adds no `timeouts` value (no task asks). The README tells
  operators to raise the Gateway timeout above `config.maxWait`.
